In standard Python (pandas), when you create a DataFrame, it lives inside your computer's single RAM memory stick. If you load 50GB of data on an 8GB laptop, it crashes.

In PySpark, a DataFrame is distributed. When you load data:

Spark splits the data into small blocks called Partitions.

It assigns different partitions to different virtual machines (workers) across a cluster.

When you run .filter() or .groupby(), all machines process their share of the data simultaneously!

Key PySpark Functions to Master
when().otherwise(): The PySpark equivalent of SQL's CASE WHEN statement or Python's if/else.

lit(): Used to add a hardcoded string or number (a literal value) into a DataFrame column.

select(): Picks specific columns to output, dropping all unmentioned columns.

Learn the when().otherwise() PatternSuppose you want to classify items into pricing tiers based on their price:If price >= 200 $\rightarrow$ "High End"Otherwise $\rightarrow$ "Budget Friendly"

from pyspark.sql.functions import col, when, lit

# Applying conditional logic using when / otherwise
df_categorized = df.withColumn(
    "price_tier",
    when(col("price") >= 200, "High End")
    .otherwise("Budget Friendly")
)

df_categorized.show()

Now we cover one of the most critical topics in real-world data engineering: Handling Missing and Null Data (isNull, dropna, and fillna).

In production data pipelines, raw data coming from APIs, databases, or user logs is rarely clean. It often contains missing (null or None) values that can break calculations or produce inaccurate reports if ignored.

Now we move to the final core pillar of PySpark basics: Joins in PySpark (inner, left, right, outer).

In real-world data engineering, data rarely lives in a single table. Transaction details, customer profiles, menu items, and delivery data are stored in separate tables. Joins allow you to merge these tables together using a common key (like item_id or customer_id).

Step 1: Create Two Tables to Join
Step 2: Understanding Join Types with SyntaxThe general syntax for joining two DataFrames in PySpark is:$$\text{df1.join}(\text{df2}, \text{on="join\_key"}, \text{how="join\_type"})$$1. Inner Join (how="inner") — The DefaultKeeps ONLY records that have a matching key in both tables.

2. Left Join (how="left") — Most Commonly Used
Keeps ALL rows from the left table (orders_df), even if there is no match in the right table (menu_df). Unmatched columns fill with null.

3. Right Join (how="right")
Keeps ALL rows from the right table (menu_df), filling missing left-side columns with null

4. Full Outer Join (how="full" or "outer")
Keeps ALL rows from BOTH tables. Unmatched keys from either side will contain null values.

What are Window Functions?
Yesterday, you mastered groupBy(), which collapses rows into a single summary row (e.g., combining 10 sales into 1 total revenue row).

Window Functions allow you to perform calculations across a set of rows (like ranking or calculating running totals) without collapsing the table. Every original row stays intact!

Key Functions We Will Cover Today
row_number(): Assigns a unique sequential number (1, 2, 3...) to each row.

rank(): Ranks rows, but leaves gaps if there are ties (e.g., 1, 2, 2, 4).

dense_rank(): Ranks rows without leaving gaps for ties (e.g., 1, 2, 2, 3).

Window.partitionBy().orderBy(): The engine that defines how data is grouped and sorted for window calculations.
